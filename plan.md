# Lunana — Full iNiR UI parity on Omarchy (Hyprland)

> Implementation plan. All verification runs in a **nested Hyprland** compositor
> against a **fixture `$HOME`** — never the live session.

---

## 0. Context & locked decisions

- **Working repo:** `/home/tenzin/development/lunana` (the Omarchy plugin suite).
- **Feature source:** `/home/tenzin/development/inir` — clean clone of `snowarch/inir`
  @ `2.33.0` (`48cdcec`), the pinned vendoring source for `scripts/vendor.py`.
- **Model B — plugin re-host.** iNiR's UI ships as Omarchy (Quattro) Quickshell **plugins**
  loaded inside the single `omarchy-shell` process, swapped via `~/.config/omarchy/shell.json`.
  Not a standalone iNiR shell.
- **Reuse lunana infra, go to full parity.** Build on `lunana-suite`, `family-cycle`,
  `scripts/vendor.py`, `contracts/host-facade-v1.json`, and the partially-built families.
  **The P01–P06 pixel-parity program is dropped** as the governing process
  (`docs/panel-family-parity-plan.md`, `.audit/*parity*`, `codex/p01*`); files stay as history.
- **Omarchy's Hyprland and its keybinds are authoritative.** Omarchy owns `~/.config/hypr/*.lua`
  (`o.bind`). Lunana keeps Omarchy's binds and adds only its own, additively, in a marked block.
- **Every iNiR UI feature present** across ii / Waffle / iRiS — nothing silently deferred.
- **Reversible interchange** lunana ↔ Omarchy stock and across families — already built in
  `lunana-suite` (install/uninstall) + `family-cycle`; extended as surfaces grow.
- **All testing in a nested Hyprland compositor** (Section 2).

### Why this is tractable
`scripts/vendor.py` copies iNiR QML into `vendor/`, rewriting `import qs.*`/`root:` to relative
imports and regenerating qmldirs, re-runnably against the inir checkout. The vendored
`CompositorService` detects the compositor from env, so **under Omarchy `isHyprland` is true,
the Hyprland branches run, and `NiriService` lies dormant** (`NIRI_SOCKET` absent). The job is
(1) fill iNiR's Hyprland *feature gaps* in the inir source, and (2) host every iNiR surface as a
lunana plugin + un-defer integrations — **not** a mass Niri rip-out or a 100-file migration.

## 1. Architecture

### 1.1 Two repos, one lever
| Side | Path | Owns | Rule |
|---|---|---|---|
| Feature source | `/home/tenzin/development/inir` | iNiR QML + runtime scripts (color pipeline, capture, record, ocr) | Hyprland fixes land here, then re-vendor |
| Delivery | `/home/tenzin/development/lunana` | `lunana.*` plugin hosts, theme/host-facade bridge, `lunana-suite`, `family-cycle`, keybind + layerrule fragments, tests | lunana-owned only |
| Vendored | `lunana/vendor/` | mechanically copied iNiR tree | **never hand-edited** (regenerated by `vendor.py`) |

Flow for any iNiR change: edit in the inir checkout → `INIR_SRC=/home/tenzin/development/inir
python3 scripts/vendor.py <paths>` → `vendor/` + qmldirs regenerate → lunana plugins pick it up.

### 1.2 Host-facade (pinned in `contracts/host-facade-v1.json`)
Omarchy injects into plugins: bar hosts get `omarchyPath, barWidgetRegistry, pluginRegistry,
barConfig, shell, manifest`; overlays get `omarchyPath, shell, manifest`. Overlay lifecycle:
`open(payloadJson)/close()/toggle()/opened`, summoned by `omarchy-shell shell toggle <id>` or a
plugin's own `ShellIpc { target }`. Theme comes from `qs.Commons` (`Color`, `Style`). Compositor
state from `Quickshell.Hyprland` + `Quickshell.Wayland`. Pinned host: Omarchy Quattro `4.0.0.alpha`.
Re-pin + re-verify before claiming another host version.

### 1.3 The repeatable adapter recipe
Every surface is one of three shapes (all already demonstrated in-repo):

**A. Bar host** (`kind: bar`) — selected by `shell.json → bar.id`:
```qml
// lunana.<family>-bar/Bar.qml
Scope {
  // optional coherence gate (e.g. yield to another family), read from shell.json via FileView
  Loader { active: <coherence>; sourceComponent: LnBar.Bar {} }  // vendored family bar
}
```

**B. Overlay / panel** (`kind: overlay` on-demand, or `kind: service` resident):
```qml
import QtQuick
import Quickshell
import qs.Commons  // required: ShellIpc lives here
Item {
  property var shell: null; property var manifest: null
  property bool opened: false
  function open(p){opened=true} function close(){opened=false} function toggle(){opened=!opened}
  ShellIpc { target: "lunana.<x>"; function toggle():void{root.toggle()} /* open/close */ }
  Variants { model: Quickshell.screens; delegate: Component {
    PanelWindow { screen: modelData; visible: root.opened; color: "transparent"
      WlrLayershell.namespace: "lunana-<x>"; WlrLayershell.layer: WlrLayer.Overlay|Top
      WlrLayershell.keyboardFocus: opened ? Exclusive : None
      // mount the vendored iNiR component; bridge qs.Commons tokens + vendor/ modules
      LnMod.<Component> { /* width/anchors from vendored Appearance.sizes */ }
    } } }
}
```

**C. Service** (`kind: service`) — background singleton/logic (e.g. `lunana.state`, `lunana.dock`,
`lunana.family`), optional `ShellIpc`.

**Register a new surface in four places:**
1. `lunana.<x>/manifest.json` (`kinds`, `entryPoints`, `x-lunana` role).
2. `scripts/lunana-suite`: `MANAGED_PLUGINS`; and if it mounts a vendored tree,
   `VENDOR_ROOTS` (content root), `VENDOR_SEED_DIRS` (sibling dirs), `VENDOR_ASSET_SEEDS`
   (fonts/`.qsb`/json referenced by relative path).
3. `lunana.family/family-cycle`: add to the owning family's overlay set in `FAMILIES`
   (a new bar family is one new `FAMILIES` line + its bar-host plugin dir).
4. `scripts/keybinds/lunana.lua`: an `o.bind` line → `omarchy-shell lunana.<x> <method>`.

### 1.4 Theme bridge
Default: defer to Omarchy's `qs.Commons` tokens (hue owned by Omarchy). A seam maps those into
iNiR's `Appearance`/`Looks`/`IrisStyle` + the `m3colors` input (already wired for the ii bar —
"Wave A step 1"). **Un-defer iNiR's Material You pipeline** as an opt-in: vendor
`scripts/colors/*` + `MaterialThemeLoader`; a `lunana.state` config flag chooses
`omarchy-tokens` (default) vs `material-you` (wallpaper-derived). Both must produce identical
token names so vendored modules don't care which is active.

### 1.5 Config
iNiR's vendored `Config.qml` drives feature behavior, reading `~/.config/inir/config.json`
(its own file, independent of Omarchy's `shell.json`). `lunana.state` grows to own the
Omarchy-facing `lunana.*` subtree in `shell.json` (enable flags, family, theme-source). New
user-facing keys follow iNiR's sync rule: `Config.qml` + consumer + the settings page in every
owning family. Strings stay wrapped in the vendored `Translation.tr(...)`.

### 1.6 Keybinds (additive, Omarchy-respecting)
`scripts/keybinds/lunana.lua` is merged into `~/.config/hypr/bindings.lua` inside the
`-- >>> lunana >>>` / `-- <<< lunana <<<` block (backed up, idempotent, removed on uninstall,
`hyprctl reload` after). It uses Omarchy's `o.bind`. **Omarchy's own binds stay untouched** —
window management, workspaces, hardware keys (vol/brightness/media), `omarchy capture`
screenshots. Lunana binds only its surfaces, e.g.:
```lua
o.bind("SUPER + SPACE",       "Lunana Overview",       "omarchy-shell lunana.overview toggle")
o.bind("SUPER + SHIFT + L",   "Lunana Left Sidebar",   "omarchy-shell lunana.sidebar-left toggle")
o.bind("SUPER + SHIFT + R",   "Lunana Right Sidebar",  "omarchy-shell lunana.sidebar-right toggle")
o.bind("SUPER + SHIFT + C",   "Lunana Control Center", "omarchy-shell lunana.control-center toggle")
o.bind("SUPER + SLASH",       "Lunana Cheatsheet",     "omarchy-shell lunana.cheatsheet toggle")
o.bind("SUPER + SHIFT + S",   "Lunana Region Snip",    "omarchy-shell lunana.region menu")
o.bind("SUPER + SHIFT + I",   "Lunana iRiS Island",    "omarchy-shell lunana.iris toggle")
o.bind("SUPER + SHIFT + W",   "Lunana Family Switch",  "omarchy-shell lunana.family cycle")
-- only where Omarchy lacks the bind; never clobber an existing o.bind (use o.rebind knowingly)
```
Surfaces reachable through iNiR's own IpcHandler targets get a thin `ShellIpc` wrapper in their
lunana host so the bind can summon them. Hardware/media keys remain Omarchy's.

### 1.7 Surface blur / shadows / animations on Hyprland
Lunana layer surfaces (`lunana-*` namespaces) get blur + shadow via **Hyprland `layerrule`s**,
and any animation presets via Hyprland `animations{}`, written to an **iNiR-owned sourced conf**
applied with `hyprctl reload`, coexisting with Omarchy's config (installed/removed by
`lunana-suite`, backed up). `place-within-backdrop` has no Hyprland analog and is dropped
(background layer renders below windows by default).

## 2. Nested Hyprland test harness (all verification runs here)

**Goal:** prove each surface renders and behaves without touching the operator's live Omarchy
session. A nested-Hyprland + fixture-home + layer-cropped-capture launcher was already prototyped
in P01 (audit TSV, branch `03eb386`); **salvage and adopt it** as the committed harness under
`scripts/test/` rather than rebuild.

### 2.1 Mechanism
- **Nested compositor:** launch Hyprland inside the current Wayland session; it opens as a
  nested window using the Wayland backend and registers its own
  `HYPRLAND_INSTANCE_SIGNATURE` under `$XDG_RUNTIME_DIR/hypr/<sig>`. Drive it with
  `hyprctl -i <sig> ...` so commands never hit the host compositor.
- **Fixture `$HOME`:** a throwaway `XDG_CONFIG_HOME` (and `HOME`) seeded with a minimal Omarchy
  config (`shell.json`, `hypr/*.lua`) + the lunana suite installed into it, so `omarchy-shell`/
  `qs` resolve the fixture, not the real config. Pin **resolution, scale, fonts, locale, and
  monitor topology** in the fixture (the P01 note flagged a nested 941×886 vs 1920×1080 mismatch —
  pin geometry via the nested Hyprland `monitor=` + window size so captures are deterministic).
- **Shell under test:** the nested Hyprland's config `exec-once`s `omarchy-shell`'s quickshell
  with the fixture, which loads the lunana plugins from the fixture plugin dir.
- **Freeze nondeterminism:** fixed clock, seeded media/notifications/weather, animations off for
  capture (toggle via the Hyprland animation path), so re-captures are stable.

### 2.2 Harness commands (`scripts/test/`)
- `nested-hypr up [--size WxH --scale S]` — start nested Hyprland + fixture home, print its
  instance sig and socket.
- `nested-hypr install` — run `lunana-suite install --yes` into the fixture; `omarchy restart shell`
  inside the nested session; wait for the shell IPC endpoint.
- `nested-hypr drive <ipc...>` — `hyprctl -i <sig> dispatch ...` / `omarchy-shell ... toggle ...`
  to exercise a surface; `nested-hypr shot <name>` — `grim` the nested output or a specific
  `lunana-*` layer, cropped, into `/tmp/lunana-nested/<wave>/<name>.png`.
- `nested-hypr logs` — tail the nested shell's journal/stderr for QML errors/warnings.
- `nested-hypr down` — `hyprctl -i <sig> dispatch exit`; remove the fixture.

### 2.3 Per-surface acceptance (applied in every wave)
1. Surface loads with **zero new QML errors/warnings** in `nested-hypr logs`.
2. Its bind/`omarchy-shell` toggle opens and closes it; focus returns on close.
3. Live data is correct (workspaces/windows/audio/etc. read from the nested Hyprland).
4. A `grim` capture is saved for the operator's review (screenshots are evidence, not a gate —
   the pixel-diff program is retired).
5. `python3 tests/test_manifests.py` + the suite smoke test stay green.
